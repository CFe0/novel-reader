# 开发记录 / 归档说明

> 本文档用于归档本项目从调研到实现的关键决策、功能清单与已修复问题。最后更新：2026-08-16。

## 1. 项目目标

一款以“本地 TXT 小说阅读”为核心、**运行在 Chrome 浏览器里**的阅读器：

> 打开 TXT → 自动识别编码 → 自动识别章节 → 起点风格阅读页直接阅读 → 关闭后自动记住位置。

纯本地运行：文件不上传、不联网、无后端、无账号、无云同步。

## 2. 产品形态演变

- 最初设想：Windows 桌面应用（曾调研 Electron / Tauri / 原生 Win32）。
- 用户确认后改为：**浏览器端 Web 应用**，阅读页 UI 对齐起点中文网网页模式（居中正文、首行缩进两字符、正文旁侧边工具、两列目录、滚动/章节两种翻页模式）。

## 3. 开源项目调研结论（要点）

- 参考了 binbyu/Reader、CatReader、tReader、ColorTxt、Readest、koodo-reader、legado 等十余个项目（详见对话记录）。
- 值得借鉴：多编码识别链路、可扩展章节规则、章节字节偏移索引、大文件分块解析、原子化本地存储、即时主题切换、目录修正。
- 必须避免：在线书源/API/爬虫（legado 已发侵权公告）、功能膨胀、无 LICENSE 的代码复用、大文件整读入内存。
- 结论：不复制任何项目代码；自己从零实现，使用 MIT License。

## 4. 技术方案

- 构建：Vite 7 + React 19 + TypeScript，`vite-plugin-singlefile` 产出单文件 `dist/index.html`（可直接用 Chrome 打开）。
- 编码识别：BOM → UTF-16 空字节模式 → 严格 UTF-8 校验 + 中文得分对比（避免 GBK 恰为合法 UTF-8 的误判）→ GB18030/Big5 打分；`TextDecoder` 解码，支持手动切换编码。
- 章节解析：可扩展规则表（第X章/回/节/卷、楔子/序章/番外、Chapter N），4MB 分块 + 行尾 carry 扫描，输出“章节名 + 字节偏移”索引，不整本读入内存（20MB 约 125ms）。
- 本地存储：IndexedDB（数据库 `txt-reader`：`books` 书架、`progress` 进度、`handles` 文件句柄）+ localStorage（`txt-reader-settings` 阅读设置）。
- 文件打开：Chrome File System Access API（保存句柄，重启后可免选文件续读），回退为文件选择器/拖拽。

## 5. 已实现功能（P0/P1 主体）

- 打开 TXT（按钮 / 拖拽 / 文件选择器）；自动编码识别 + 手动切换并即时重新解析。
- 章节识别与目录：两列网格、搜索、点击跳转、面板可拖拽调宽（300–900px，宽度记忆）。
- 起点风格阅读页：纸张式正文区（独立底色与两侧背景区分）、首行缩进、章节标题、正文旁右侧工具栏（目录/设置/主题色板）。
- 阅读设置：字体、字号（Ctrl+±）、行距、段距、对齐、正文宽度；主题（日间/米黄/护眼绿/夜间）即点即生效并自动保存。
- 阅读模式：章节翻页（显示上一章/下一章，进度显示在顶栏）与滚动翻页（章末自动加载下一章，隐藏翻页按钮与底部栏）。
- 滚动模式性能：自动卸载当前章节之前 15 章以外的 DOM 与文本缓存，滚动位置无跳变补偿。
- 进度自动保存：章节 + 章节内滚动偏移，防抖写入；关闭/刷新前兜底保存；重新打开精确恢复。
- 本地书架：最近阅读、收藏、全部书籍；窗口状态（阅读设置、目录宽度）记忆。

## 6. 已修复的关键问题

- **进度被覆盖导致“重新打开回到开头”**：开发模式 React StrictMode 先执行一次假挂载/假卸载，假卸载的兜底保存把未恢复的进度（0 章 0 偏移）写库覆盖了真实进度。修复：进度读取完成前禁止兜底保存，且仅在页面真正定位过滚动位置后才允许保存。
- **GBK 字节恰为合法 UTF-8 导致编码误判**：改为“能解码”之外再对比解码内容的中文得分。
- **UTF-16 小文件识别失败**：降低空字节模式判定的样本量门槛。
- **大文件一次性读入**：改为分块扫描 + 章节字节偏移懒加载。

## 7. 数据存储位置（用户可自行查看）

- IndexedDB（书架/进度/句柄）：`C:\Users\<用户名>\AppData\Local\Google\Chrome\User Data\Default\IndexedDB\http_localhost_5173.indexeddb.leveldb`（开发服务器）；双击打开单文件时为 `file__...indexeddb.leveldb`。
- 阅读设置：`C:\Users\<用户名>\AppData\Local\Google\Chrome\User Data\Default\Local Storage\leveldb\`。
- Edge 同理，目录为 `...\Microsoft\Edge\User Data\Default\...`，数据与 Chrome 互相独立。
- 直观查看：Chrome F12 → Application → IndexedDB / Local Storage。

## 8. 迁移到其他电脑

- 仅阅读：复制 `dist/index.html` 到新电脑，Chrome 打开即用；书架/进度需在新电脑重新导入（数据在浏览器里，不随文件走）。
- 继续开发：复制整个项目目录（排除 node_modules、dist、.tmp），新电脑安装 Node.js 后 `npm install && npm run dev`。

## 9. 部署与在线书库（2026-08-17）

- 线上地址：https://cfe0.github.io/novel-reader/ （GitHub Pages，Actions 自动构建发布）。
- 部署链路：本地 `git push`（SSH，走 ssh.github.com:443，绕开被挡的 github.com 网页 IP）→ GitHub Actions `npm run build` → 发布 `dist/`。
- 在线书库：小说放 `public/books/*.txt`，构建时自动生成书单 `index.json` 与章节索引 `<书名>/chapters.json`，并把每章拆分为独立小文件（`chapters/00000.txt`…），阅读器按章懒加载（普通 GET + 15s 超时重试），手机上打开快且不会卡死。
- 手机端：沉浸式正文（点击屏幕唤出悬浮工具栏）、目录/设置半屏弹层、工具栏悬浮不改变正文排版。
- 新增主题：浅绿 `#E6F4DF`、豆绿 `#DDE8D2`；新增字体：思源黑体 CN。
